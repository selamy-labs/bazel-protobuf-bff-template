## R2 Isolation policy (validated on the authoring host)

**Probe** (2026-10-29), on Ubuntu 24.04 with `kernel.apparmor_restrict_unprivileged_userns=1`:

- Bazel 9.3.1 did not register `linux-sandbox` ("no strategy with that identifier was
  registered").
- Running the helper directly failed with `linux-sandbox-pid1.cc:205: "mount": Permission denied`.
- `unshare --user --map-root-user` failed writing `uid_map`.

Without an explicit strategy, Bazel's default `sandboxed` falls back to `processwrapper-sandbox`,
which has no namespace isolation. That is the silent weakening the spec forbids.

**Decision**:

- `.bazelrc` uses `common --enable_platform_specific_config` with
  `build:linux --spawn_strategy=linux-sandbox` and `--sandbox_default_allow_network=false`. Bazel
  therefore errors instead of falling back.
- `build:weak-isolation --spawn_strategy=processwrapper-sandbox` is the explicit opt-in.
  `tools/verify.sh --weak-isolation` passes it and stamps the receipt with `isolation: weakened`.
- The preflight probes with the installed Bazel's own `linux-sandbox` helper, which is the ground
  truth, and prints these remediations:
  1. An AppArmor profile that grants `userns` to the Bazel sandbox helper. Needs admin.
  2. `sysctl kernel.apparmor_restrict_unprivileged_userns=0`. Needs admin and is host-wide, so it
     is a weaker choice.
  3. CI or a container where this is configured.
  4. The explicit `--weak-isolation` opt-in, with labeled evidence.
- The authoring host is **not** modified; that is out of authority. M1 evidence from it is
  labeled `weakened`.
- CI (hosted ubuntu-24.04) lifts the restriction on the disposable VM with
  `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` and verifies at full
  isolation. This is unconfirmed until a hosted run exists (spec A2).

**macOS**: `build:macos --spawn_strategy=darwin-sandbox`. Unverified in M1.

## R3 Where checks run

- **Hermetic tests** (`bazel test //...`): the suppression-ban Go unit tests and fixtures, the
  Spec Kit manifest check, the Bzlmod policy test, and the fixture tests for every native check.
- **Native checks over the real file set**, using Bazel-built pinned binaries: `secrets`, `typos`,
  `suppression-ban`, `shellcheck`, `actionlint`/`zizmor` and `buildifier --mode=check`.
  - They run from `tools/verify.sh` over `git ls-files -co --exclude-standard -z`.
  - Bazel globs can't see the whole checkout, and the reference's absolute-path workaround is
    non-hermetic.
  - This is the "native kind" from the parent R-08 runner design. M5 replaces it with the
    registry and runner.
- **Lock policy**:
  - `.bazelrc` sets `common --lockfile_mode=error`.
  - The defect fixture copies only `MODULE.bazel`/`MODULE.bazel.lock` and a stub `BUILD` into a
    temp workspace, sharing the repository cache, and expects failure after an unlocked edit.

## R4 Spec Kit check (offline)

Regenerating the scaffold offline needs a hermetic Python environment with the Spec Kit CLI and
its dependencies. That would bring rules_python, whose only consumer would be this check.
Instead:

- **Hermetic.** `tools/speckit/scaffold.sha256` is generated by `bootstrap.sh manifest` from a
  pinned regeneration. An offline Bazel `sh_test` checks every vendored file against it, and fails
  on any change, extra file or missing file in the scaffold paths.
- **Provenance.** `bootstrap.sh verify` regenerates from the pinned commit (network) and checks
  that both the scaffold *and the manifest* match. It runs in `tools/verify.sh` unless `--offline`
  is given. CI always runs it.

**Limit (stated)**: a hand edit that also updates the manifest passes the offline test. Only the
provenance step catches it.

FR-013 ("offline from a hash-pinned archive") is reworded to match this design. The divergence
from the parent T007 wording is recorded there.

## R5 Suppression ban (Go, quality module)

- `@bff_template_quality//checks/suppression` is a Go binary with stable codes:

  | Code | Pattern |
  | --- | --- |
  | S001 | `//nolint` |
  | S002 | `eslint-disable` |
  | S003 | `@ts-ignore` / `@ts-expect-error` |
  | S004 | `buf:lint:ignore` |
  | S005 | coverage-ignore markers |
  | S006 | `shellcheck disable` |
  | S007 | `# noqa` / `type: ignore` |

- Patterns are matched outside string literals only to the extent of line-level heuristics.
  Fixtures pin the behavior.
- The vendored Spec Kit paths are exempt by path, and the exemption list is itself verified by the
  manifest.
- The rule definitions live in the binary's source.
- The check file is excluded by an explicit self-exemption: its own pattern table and fixture
  directory.

## R6 Budgets method

- `tools/bench/measure.sh` takes `--cold N` and `--warm N`.
- A **cold** run uses a fresh `--output_user_root` and an empty `--repository_cache`, with the
  network allowed.
- A **warm** run reuses both.
- Peak memory is sampled from the **server's process tree**, every 0.5 s, by summing RSS from
  `/proc/<pid>/status` over the server and its descendants. The server is a daemon and not a child
  of the client, and its actions descend from the server, so `/usr/bin/time` on the client would
  understate memory. Sampling can miss short spikes, and this limit is stated in every record.
- Output goes to `docs/budgets/<os>-<arch>-<ncpu>c.json`.
