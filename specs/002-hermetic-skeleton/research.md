## R2 Isolation policy (validated on the authoring host)

**Probe** (2026-10-29), on Ubuntu 24.04 with `kernel.apparmor_restrict_unprivileged_userns=1`:

- Bazel 9.3.1 did not register `linux-sandbox` ("no strategy with that identifier was
  registered").
- Running the helper directly failed with `linux-sandbox-pid1.cc:205: "mount": Permission denied`.
- `unshare --user --map-root-user` failed writing `uid_map`.

Without an explicit strategy, Bazel's default `sandboxed` falls back to `processwrapper-sandbox`,
which has no namespace isolation. That is the silent weakening the spec forbids.

**Decision**:

- `.bazelrc` uses `common --enable_platform_specific_config` with
  `build:linux --spawn_strategy=linux-sandbox` and `--sandbox_default_allow_network=false`. Bazel
  therefore errors instead of falling back.
- `build:weak-isolation --spawn_strategy=processwrapper-sandbox` is the explicit opt-in.
  `tools/verify.sh --weak-isolation` passes it and stamps the receipt with `isolation: weakened`.
- The preflight probes with the installed Bazel's own `linux-sandbox` helper, which is the ground
  truth, and prints these remediations:
  1. An AppArmor profile that grants `userns` to the Bazel sandbox helper. Needs admin.
  2. `sysctl kernel.apparmor_restrict_unprivileged_userns=0`. Needs admin and is host-wide, so it
     is a weaker choice.
  3. CI or a container where this is configured.
  4. The explicit `--weak-isolation` opt-in, with labeled evidence.
- The authoring host is **not** modified; that is out of authority. M1 evidence from it is
  labeled `weakened`.
- CI (hosted ubuntu-24.04) lifts the restriction on the disposable VM with
  `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` and verifies at full
  isolation. This is unconfirmed until a hosted run exists (spec A2).

**macOS**: `build:macos --spawn_strategy=darwin-sandbox`. Unverified in M1.

## R3 Where checks run

- **Hermetic tests** (`bazel test //...`, with cached results disabled): the Go unit tests, the
  Spec Kit manifest check, the policy tests and every native-check fixture.
- **Native checks over the real file set**: `tools/checks/native.sh` runs the pinned binaries from
  the repository root over the NUL-delimited lists from `tools/checks/inventory.sh`. Bazel globs
  can't see the whole checkout. This is the "native kind" of the parent R-08 runner design; M5
  replaces the orchestration, not these definitions.
- **Toolchain witnesses that need a real Bazel**: `tools/policy/lock_fixture.sh` copies the module
  files into a temp workspace that shares the repository cache. It witnesses the lock check, a
  checksum mismatch, and ambient rc isolation, the last with a control proving raw Bazel obeys the
  hostile rc.

## R4 Spec Kit check

- **Offline.** `tools/speckit/scaffold.sha256` is generated by `bootstrap.sh manifest`. An offline
  Bazel `sh_test` checks every vendored file against it and fails on any changed, extra or missing
  file in the scaffold paths.
- **Provenance.** `bootstrap.sh verify` regenerates from the pinned commit (network) and checks that
  both the scaffold *and the manifest* match. It runs in `tools/verify.sh` unless `--offline` is
  given, and CI never passes that flag. It uses the pinned uv, managed CPython 3.12.15,
  `tools/speckit/requirements.lock` (hashes) and `tools/speckit/build-constraints.txt`.

**Limits (stated)**: a hand edit that also updates the manifest passes the offline test, so only the
provenance step catches it. Build constraints are version-only, because uv has no hash mode for
them. CPython's identity rests on the checksums embedded in the pinned uv.

## R5 Suppression ban (Go, quality module)

- `@bff_template_quality//checks/suppression:suppression-ban` has stable codes S001–S012, defined in
  `rules.go`. A code exists only for an inline control that a tool here honors; the pinned typos
  honors none, so it has no code.
- Matching is line-level heuristics, not parsing, and fixtures pin the behavior. It is
  case-insensitive. Block-comment rules (S002, S005) match across lines because their tools accept
  that, and report the line where the directive starts. Line rules stay per-line, so unrelated
  adjacent lines cannot combine into a false positive.
- NUL bytes are removed, not treated as a binary marker. Markdown is skipped, because a directive in
  prose has no effect.
- Exemptions are path **and** content hash, from `tools/speckit/scaffold.sha256` and
  `testdata/fixtures.sha256`, so an unknown lookalike or a changed enrolled file is scanned. The only
  other exemption is the exact path of `rules.go`, which must contain the banned strings.
- The S002 spellings were observed against a host ESLint 6.4.0 as diagnostic evidence. They must be
  re-witnessed with the pinned ESLint when it arrives (parent T047).

## R6 Budgets method

`tools/bench/measure.sh` measures a clone of a clean HEAD. It separates bootstrap, the first verify,
an unchanged warm verify, a verify after a source edit, and a downloads-disabled run; its header
defines each. Peak memory is sampled PSS of the verifier's and the Bazel server's process trees, so
shared pages are not double-counted and the sampler is excluded. Sampling can miss short spikes, and
every record says so. Output goes to `docs/budgets/<os>-<arch>-<ncpu>c.json`.
