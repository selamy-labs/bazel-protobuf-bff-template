## R4 Coverage (Q5)

- Go's cover tool reports statements, not branch outcomes, and does not probe inside `&&` and `||`. Root's probe of gobco 1.3.4 under Go 1.27 (`m9-go-branch-probe-result.json`, synthetic fixture, no Bazel integration): the tool has `-branch`; on the fixture it reported Condition 2/2 and Branch 2/2 while native statements were 50% and the `select` cases were never executed. It can be qualified only as a branch sub-metric: the probe covered `if` branches only, and an uncalled `select` is not counted even with `-branch`; it is never a complete Go branch claim and never a waiver. Decision: probe `gobco` with adversarial fixtures and accept only the constructs it reports, named as such; Go branch outcomes stay a blocking owned task until measured; browser coverage through Playwright's V8 coverage into the existing merger; floors unchanged and only rising.
- Probed at T007 (record and fixture in `m9/probes/gobco-probe-20261102.txt` and `gobco-fixture-20261102`, outside the repository; gobco v1.3.4 by module ziphash, installed into a scratch directory with the pinned Go 1.27.3 SDK, no Bazel integration): over the adversarial fixture (early returns, a switch default never taken, a loop exit never taken, a short circuit, a `select` default never taken) condition mode reports 8 of 14 and `-branch` 7 of 10, statements 76.5 percent. What it reports, by construct: each early-return guard as a condition with both outcomes, the implicit else being the false outcome; the switch default only as the last case's condition never false, no default construct named; the loop exit only as the body's condition never true, the range loop itself not a construct; the short circuit's right operand named as never evaluated in condition mode and dropped with the left operand in `-branch` mode, which therefore says nothing about operands; the `select` default invisible in both modes. Reading: gobco is a condition-outcome sub-metric, qualifiable for `if`, `switch` cases and loop conditions, with its condition mode the more complete; `select` cases and operand pairs under `-branch` are gaps it must never be claimed for. Binding under Bazel (an instrumenting run beside the coverage leg) and the Playwright V8 probe remain open under T007; Go branch outcomes stay a blocking owned task.

## R8 The archive primitive (FR-015)

- `git bundle verify` reads only the header; a truncated bundle passes it and fails a fresh clone, so the restore is the proof. The primitive owns a temporary directory, removes nothing unowned, refuses links and existing outputs, computes the digest and mode inside the owned directory before publication, publishes with `ln -T` so a directory or link that arrived at the destination meanwhile is refused rather than entered, and reports nothing unless the published path is the owned bundle; the handoff records eligibility only behind a verified archive. An independent output control found the earlier text entering a late-arriving directory and reporting an archive with an empty digest; that case is now a control. 27 primitive and 9 handoff controls pass externally. They are prevention for the future; they recover nothing, and the 2026-11-01 loss stays unrecovered regardless of what they show.

## R13 Reachable vulnerabilities (T023)

- govulncheck (`golang.org/x/vuln` 1.9.0, with `x/telemetry` and `x/sys` as its dependencies, all BSD-3-Clause read from the modules) is pinned in the quality module and built through Bazel. Source mode needs `go list` over the module, which this Bazel-only tree cannot provide for its generated packages; binary mode reads the built binary's symbol table, which is the hosted boundary itself, so that is the mode used. The database is fetched from `vuln.go.dev` at run time: the probe is networked, and no offline claim is made. First run at `80b91d2` against the production and development server binaries (record `m9/probes/vuln-probe-20261101.txt`, outside the repository): the twelve third-party modules clean; one reachable standard-library vulnerability, GO-2026-6809 in `crypto/x509` `Certificate.Verify`, fixed in go1.27.3, which the next revision pins; after the move both binaries scan clean, and the rescan taught one thing: the production binary's target transitions configuration, so `bazel-bin`'s convenience symlink still held the old binary, and the output `cquery` names is the one to scan. The check `vulnerabilities` is bound at full with the database named in the registry, declared as needing the network; its witness writes a local database in the layout govulncheck reads (`index/db.json`, `index/modules.json`, `index/vulns.json`, `ID/<id>.json`, the entry carrying the `database_specific.url` govulncheck dereferences) and runs the real tool against a real server binary: a reachable planted advisory is named, one fixed before the binary's Go version and one on a module the binary lacks are not. Telemetry is off in the check: govulncheck links the Go telemetry library, which otherwise starts a child.
- Found on the first hosted pull request, where the scan measured 0 reachable and the check still failed: a clean verdict was overwritten by the cleanup. On a host with `go` on `PATH`, `govulncheck -version` runs `go env GOVERSION`, which downloads the toolchain `go.mod` names into the temporary `HOME` as a read-only module cache, so the trap could not remove it. Reproducing that locally exposed a second cause: the check's `GOTELEMETRY=off` was never read by the telemetry library, whose only switch is its mode file, so its crash-monitor child outlived the scan and wrote under the configuration directory during the trap, leaving `Directory not empty` intermittently, and that directory was the host's whenever `XDG_CONFIG_HOME` was set. The trap now makes the tree writable, `GOTOOLCHAIN=local` stops the download, and the configuration directory and an `off` mode file live under the temporary `HOME`. The witness plants a `go` that leaves the read-only tree and reads the telemetry directory, since a scan is too quick to lose that race on demand.

## R9 The budget comparator and its base

- `floors-from-base` builds the evaluator from the base commit and compares the proposal's coverage floors with it (spec 007 R6). The base `e3b3b34` holds no comparator for complexity or mutation budgets, so a proposal that adds `quality/complexity_budgets.json` would be compared by nothing: the check passes without judging, exactly the gap `docs/quality/capability-states.md` already names for an adapter the proposal pins.
- Decision: the comparator lands in one anchor commit with the first budgets, is reviewed independently at that SHA with its own negative control recorded, and every weaker-proposal witness after it names a base at or after that anchor. Until the anchor is accepted, the direction controls run only as fixtures inside the check's own test, which is advisory for the base path and is recorded as partial, not enforced.
- At T012a: `complexity-from-base` runs the base's own comparator (`checks/complexity:complexity_bin`, built in the base worktree as `floors-from-base` builds its evaluator) against the tested tree's budgets; a base that predates the comparator says it holds none and compares nothing, so the check is visible in every receipt and judges once the named base is at or after the anchor `6436306`. The direction control is enforced from that base onward; at `e3b3b34` it remains partial.
- At T013, the TypeScript ceiling joins the same file: `quality/complexity_budgets.json` carries a `typescript` section (measured at `a287ed7`, cyclomatic 12) that `web/lint/eslint.config.mjs` reads for its `complexity` rule, so the ceiling is one policy input and the base's comparator judges its direction with the Go ceilings: it may only fall, and the section may not go; a section appearing is stricter. The Go check measures nothing in it. The section is optional, so a budgets file from before it loads, and a base from before it compares nothing about it; a base between the comparator's anchor and this change would refuse to load the proposal's file and the check would say it could not judge, which is the honest outcome until the named base moves past this change.
