## Order of work

Plan, research, tasks and matrix came before code, and scratch probes came before the plan's later revisions. Red first means the test failed for its intended reason, on the code before the fix.

| Change | Red first |

| Receipt measurement summary (review of the anchor) | Yes |
| A supplied base binds a leg that reads none (review of `33e6a55`) | Yes |
| Legs, CI, merger, evaluator, base naming, hook setting | Written with their tests, and not claimed red first |

Found by a rehearsal in a disposable clone, the first real base build: Bazel's `//...` walked into the base worktree under `.git`, and `toolchain-fixtures` failed on a link there. The M5 push worktree has the same exposure. `REPO.bazel` now ignores `.git`, with a control.

Found by running real tools, not by a test written first: `.bazelrc` parsing consumed the filter's backslash, so the quality module was silently uninstrumented; Bazel calls the report
generator with other arguments; the `e2e` leg's subtraction would have removed its own targets; prek gives a new branch a real `--from`.

## Final results by scope

**Base flows, at `6582ef3`.** The compiled-base composition was run with real tools: the proposal built and its own evaluator passed, and the evaluator built from the base rejected it, naming the lowered `go-root` floor and S001.

The CLI flows of spec 007 R6 were replayed through the `policy` leg, and not as the literal unsharded commands. An independent reviewer approved that reduction, because each unsharded repeat costs a full verifier. `reviewed` exited 0 in 364 s with `floors-from-base` passed, `none` exited 11 in 290 s, and `head` exited 11 in 304 s. The `sha` case was stopped by agreement and is not a result. The remaining permutations were not run. Their boundaries are covered by the standing fixtures and the full gates.

## Results that were not credited

- The edited sample at `6582ef3` earns no performance credit. The harness's comment was not gofmt-clean, so `format-go` failed it 2.5 s in, which is the harness's defect and not the template's. The next invocation, `--offline`, deleted that run's receipt, so its complete check list is unknown: only `format-go` left a retained log. The harness still exited 0 and wrote a record, with `failed_runs` as the only sign.
- The first harness repair, `a5ebd95`, left a real gap: a refused run deleted its work tree with its Bazel servers still alive. A stub could not show that. A control with real servers showed it red on `a5ebd95` and passed on `e16718d`, with a same-command server left running.
- Two attempts of that control failed through fixture bugs, and earned nothing. One candidate's bytes were superseded when the suppression ban refused a ShellCheck directive, and its controls were rerun on the replacement.

- The first `pure = "on"` build left a stale `floors` binary in `bazel-bin`, and one all-absent measurement came from it. It failed closed. Removing the transition ended it. `f4bb2aa` therefore cannot build as a base, which is harmless.
- The first probes reported empty TypeScript coverage partly because the probe's merger read only `*.dat`. Research records the corrected attempts.
- Early research called the quality module 72 to 75 percent from an LCOV path match. Neither number is used.
