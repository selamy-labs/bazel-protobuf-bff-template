# api

## Purpose

This directory holds the schemas that are the single source of truth between the browser and the
BFF. Go and TypeScript code is generated by the build and is never committed.

## What to read first

- [template/notes/v1/notes.proto](template/notes/v1/notes.proto) is the contract.
- [docs/api-style.md](../docs/api-style.md) is the API-style ledger.

## Change a schema

```sh
$EDITOR api/template/notes/v1/notes.proto
tools/verify.sh
```

`proto-format`, `proto-lint` and `proto-breaking` name what failed. A wire-incompatible change needs
a new package version, such as `template.notes.v2`.

## The baseline

`BASELINE` holds a full commit hash, and the working schema is compared with the schema in that
commit. A missing commit, a shallow clone or a commit outside the current history fails the check.

To accept a released schema as the new baseline, put its commit hash in `BASELINE` and have that
change reviewed. A copy of this template with fresh history puts `bootstrap` in `BASELINE` in the
commit that adds its first schema, then replaces it with that hash in the next commit. The marker is
refused once an earlier commit has a schema.

## Update dependencies

TypeScript packages are in `package.json`:

```sh
tools/bootstrap/bazel.sh run --lockfile_mode=update @pnpm//:pnpm -- --dir "$PWD" install --lockfile-only
```

Go modules are in `go.mod`. `go mod tidy -e` keeps generated-code imports through `tools.go`. Its
errors about the generated packages are expected, because those packages exist only in the build.
